# RBAC 架构设计图

> 目标：用图形化和分层方式描述 `user -> role -> permission -> backend api` 的鉴权链路，方便快速理解整体架构。

---

## 1. 核心链路

```text
┌─────────────┐
│    User     │
└──────┬──────┘
       │ 绑定
       ▼
┌─────────────┐      ┌──────────────┐
│    Role     │─────▶│  Permission  │
└──────┬──────┘      └──────┬───────┘
       │ 绑定               │ 绑定
       ▼                    ▼
┌─────────────┐      ┌──────────────┐
│ UserRole    │      │ PermissionAPI│
└─────────────┘      └──────┬───────┘
                             │
                             ▼
                    ┌──────────────────┐
                    │ Backend Endpoint  │
                    └──────────────────┘
```

---

## 2. 请求鉴权架构

```text
客户端请求
   │
   ▼
┌──────────────────────┐
│  AuthMiddleware       │
│  - 处理白名单接口     │
│  - 解析 JWT           │
│  - 写入请求上下文     │
└─────────┬────────────┘
          │
          ▼
┌──────────────────────┐
│ PermissionMiddleware  │
│  - 查 Redis           │
│  - Redis 未命中查 DB  │
│  - 校验用户权限       │
│  - 返回 401/403       │
└─────────┬────────────┘
          │
          ▼
┌──────────────────────┐
│   业务处理层          │
└──────────────────────┘
```

---

## 3. 权限校验顺序图

```text
请求进入
  ├─> 是否公开接口？
  │     ├─ 是 → 放行
  │     └─ 否 → 继续
  ├─> 是否白名单用户？
  │     ├─ 是 → 放行
  │     └─ 否 → 继续
  ├─> Redis 是否存在接口权限映射？
  │     ├─ 是 → 读取 permission_code
  │     └─ 否 → 查询数据库并回填 Redis
  ├─> 接口是否配置权限？
  │     ├─ 是 → 继续鉴权
  │     └─ 否 → 按策略处理（拒绝 / 记录日志 / 公开）
  ├─> 用户是否拥有权限？
  │     ├─ 是 → 放行
  │     └─ 否 → 403
```

## 4. 组件职责图

### 4.1 AuthMiddleware

```text
┌────────────────────────────┐
│ AuthMiddleware             │
├────────────────────────────┤
│ 1. 识别公开接口            │
│ 2. 解析 Authorization      │
│ 3. 校验 JWT                │
│ 4. 构建当前用户上下文      │
│ 5. 识别系统白名单账号      │
└────────────────────────────┘
```

### 4.2 PermissionMiddleware

```text
┌────────────────────────────┐
│ PermissionMiddleware       │
├────────────────────────────┤
│ 1. 获取请求方法与路由      │
│ 2. 查 Redis 接口权限映射   │
│ 3. Redis miss 查数据库     │
│ 4. 比对用户权限集合        │
│ 5. 决定放行或拒绝          │
└────────────────────────────┘
```

## 5. 缓存架构

```text
┌──────────────────────┐
│      Redis           │
├──────────────────────┤
│ rbac:user:roles:*    │
│ rbac:user:perms:*    │
│ rbac:api:*           │
└─────────┬────────────┘
          │ 未命中
          ▼
┌──────────────────────┐
│    Database          │
└──────────────────────┘
```

### 5.1 缓存用途

- `rbac:user:roles:{user_id}`：用户角色集合
- `rbac:user:perms:{user_id}`：用户权限集合
- `rbac:api:{method}:{normalized_path}`：接口权限映射

---

## 6. 白名单架构

### 6.1 公共白名单

适合不需要登录的接口：

- 登录
- 注册
- 验证码
- 健康检查
- OpenAPI 文档

### 6.2 系统白名单

适合拥有全局权限的账号：

- 超级管理员
- 运维账号
- 初始化系统账号

建议使用：

- `user_id` 白名单
- 或数据库字段 `is_super_admin`

而不是长期依赖用户名字符串。

## 7. 风险点图示

```text
┌────────────────────────────────────────────┐
│ 风险 1：未配置权限的接口默认放行           │
│ 风险 2：白名单范围过大                     │
│ 风险 3：路径未规范化导致匹配失败           │
│ 风险 4：权限变更后缓存未及时刷新           │
│ 风险 5：数据权限未与功能权限区分           │
└────────────────────────────────────────────┘
```

---

## 8. 结论

这套架构适合你的平台，建议采用：

- `user -> role -> permission` 作为授权模型
- `PermissionMiddleware` 负责接口级鉴权
- Redis 负责接口权限缓存
- 白名单只处理少量特殊场景
- 默认拒绝未配置权限的生产环境接口
