## 一、上下文压缩功能

实现位置： `packages/compaction/` （4 个子包）

| 包                                          | 作用                                | ctx 键                 |
| :------------------------------------------ | :---------------------------------- | :--------------------- |
| `compaction/compaction/`                    | 抽象接口定义                        | `ctx.compaction`       |
| `compaction/compaction-basic/`              | 默认实现——token 压力检测 + LLM 摘要 | 提供 `ctx.compaction`  |
| `compaction/compaction-tool-result-pruner/` | 预处理：裁剪过大的工具输出          | `ctx.toolResultPruner` |
| `compaction/command-compact/`               | `/compact` 命令                     | 用户手动触发           |

工作原理：

1. 每步之前用 `ctx.tokenMeter` 测量上下文总 token 量
2. 超过阈值（默认 80% 上下文窗口）→ 先裁剪大工具输出 → 再用 LLM 对历史头部做摘要
3. 摘要替换原始消息，旧内容保留在 append-only 日志中但不再发给模型

相关的上下文注入插件： `packages/context/`（workspace 指令、时间、tmux 等），压缩后会自动重新注入最新上下文。

## 二、工作模式

这里其实是 两套独立系统：

### A. Agent 预设（你看到的"标准/PTC/极简/创造"）

实现位置： `packages/preset/agent-presets/` + `apps/cli/config/agent-presets/`

| 预设 ID    | UI 名称  | 差异                                                      |
| :--------- | :------- | :-------------------------------------------------------- |
| `standard` | 标准模式 | 完整 Agent：shell、fs、技能、plan、压缩、子 Agent、工作流 |
| `code`     | PTC 模式 | 标准 + Code Mode（`run_code` 工具）                       |
| `minimal`  | 极简模式 | 只有 bash + 文件编辑器，无压缩/技能/plan                  |
| `cordis`   | 创造模式 | 标准 + Cordis 自修改工具 + 编创技能                       |

每个预设就是一个 `agent.cordis.yml` 文件，定义该模式下加载哪些插件。

前端 UI： `packages/client/ui-agent-preset/`

### B. 权限预设（你看到的"只读/工作区写入/完全访问"）

实现位置： `packages/interaction/permission-presets/`

| 预设                 | 沙箱模式   | 审批策略 |
| :------------------- | :--------- | :------- |
| `read-only`          | 只读沙箱   | 需审批   |
| `workspace-write`    | 工作区可写 | 需审批   |
| `danger-full-access` | 无限制     | 无需审批 |

前端 UI： `packages/client/ui-permission-presets/`

两套互相独立——预设决定"有什么工具"，权限决定"工具能做什么"。

## 三、前端交互：对话 vs 轨迹

核心架构： 前端也是 Cordis 插件树，通过 Slot 插槽系统 组合 UI。

### 对话视图（Chat View）

实现位置： `packages/client/ui-conversation/`

src/client/

├── apply.ts                    # 所有插槽注册

├── chat/ChatView.tsx           # ★ 主聊天视图

├── chat/ChatNodeSeat.tsx       # 每条消息的渲染容器

├── chat/register-node-renderers.ts  # 注册各类节点渲染器

├── skeleton/ConversationRoot.tsx    # 滚动容器 + 输入框定位

├── skeleton/InputBar.tsx       # 输入栏

└── conversation-nodes/         # 事件→节点的数据组装

### 轨迹视图（Trajectory View）

实现位置： `packages/client/ui-trajectory/`

src/client/

├── index.ts                    # 注册为 conversation.view 的第二个 tab

├── TrajectoryView.tsx          # ★ 主轨迹视图容器

├── TrajectoryTable.tsx         # 事件列表/表格

├── TrajectoryTimeline.tsx      # 时间线概览

├── TrajectoryTurn.tsx          # Turn/Step 渲染

└── trajectory-snapshot-builder.ts  # 独立的视图数据构建

### 两者关系

它们是 同一个 slot 环（`conversation.view`）里的两个 tab：

ConversationSessionHeader

  ├── Tab: "对话"  (order: 0, id: 'chat')     ← ui-conversation 注册

  └── Tab: "轨迹"  (order: 10, id: 'trajectory') ← ui-trajectory 注册

点击 tab 切换视图，底层数据都来自同一个 session event 流，只是渲染方式不同：

- 对话 = 用户视角，看到对话气泡
- 轨迹 = 开发者视角，看到每个 turn/step/tool-call 的时序、token 消耗、耗时

## 整体前端架构图

apps/web/src/main.ts  (Vite 入口，很薄)

​    └─ packages/client/web/  (启动内核 AppWebEntry)

​        └─ Cordis Loader 加载所有 client 插件

​            ├── ui-layout/        → AppFrame (三栏布局)

​            ├── ui-sidebar/       → 左侧导航

​            ├── ui-conversation/  → 对话视图 + 会话骨架

​            ├── ui-trajectory/    → 轨迹视图

​            ├── ui-tool/          → 工具调用渲染

​            ├── ui-agent-preset/  → 工作模式选择器

​            ├── ui-permission-presets/ → 权限模式选择器

​            └── ...其他 ui-* 插件

所有 UI 组件都通过 `ctx.slots.register()` / `ctx.slots.inject()` 注册到插槽系统，最终由 `renderSlot()` 渲染——所以前端也是完全插件化的，你可以写自己的 client 插件替换或扩展任何 UI 部分。
