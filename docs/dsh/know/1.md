## DeepSeek Harness (dsh) 全面分析

### 一、它是什么？

DeepSeek Harness（简称 `dsh`）是 DeepSeek AI 开源的 AI Agent 运行框架。你可以把它理解为一个"AI 智能体操作系统"——它提供了让大模型（LLM）以 Agent 形式运行所需的一切基础设施：工具调用、会话管理、文件操作、终端控制、Web UI 等等。

核心设计哲学：万物皆插件（Everything is a Plugin），底层基于 [Cordis](https://github.com/cordiverse/cordis) 框架实现。

------

### 二、整体模块划分

整个项目是一个 pnpm monorepo，约 226 个包，可以归纳为以下几个大模块：

#### 1. 核心脊柱（Core Spine）

| 模块                 | 作用                                                         |
| :------------------- | :----------------------------------------------------------- |
| `core/session`       | 会话日志——所有对话的 append-only 事件流，持久化、回放、fork 都基于它 |
| `core/system-prompt` | 系统提示词组装——把各插件注册的 prompt 片段和工具 schema 拼成完整 system prompt |
| `core/tools`         | 工具注册表 + 执行管线——管理所有 model 可调用的工具           |
| `core/agent`         | Agent 接口 + 注册表——定义 Agent 生命周期事件                 |
| `core/agent-loop`    | 默认 Agent 循环驱动——实现 turn → step → LLM 调用 → 工具执行 的循环 |
| `llm/llm`            | LLM 适配器接口——模型调用的抽象层，可接不同后端               |

#### 2. 能力层（Capability Families）

每个"能力"都是三件套：接口定义 → 实现提供者 → 消费者（通常是工具）

| 能力            | 说明                                           |
| :-------------- | :--------------------------------------------- |
| `fs/`           | 文件系统——读写文件、搜索文件                   |
| `shell/`        | Bash 执行——命令行操作                          |
| `terminal/`     | 持久 PTY 终端——保持终端会话                    |
| `subprocess/`   | 进程管理——子进程生命周期                       |
| `sandbox/`      | 沙箱隔离——bwrap/Landlock/Seatbelt 限制进程权限 |
| `web/`          | Web 能力——搜索、抓取网页                       |
| `lsp/`          | 语言服务器——代码智能分析                       |
| `subagent/`     | 子 Agent——委托子任务给其他 Agent               |
| `compaction/`   | 上下文压缩——长对话自动精简                     |
| `code-runtime/` | 代码执行——在 worker 线程运行代码               |
| `skill/`        | 技能系统——可加载的预设行为指导                 |
| `workflow/`     | 工作流引擎——多步骤编排                         |

#### 3. 数据与持久化层

| 模块           | 说明                          |
| :------------- | :---------------------------- |
| `session/`     | 会话持久化——JSONL/SQLite 后端 |
| `storage/`     | 通用存储——非会话数据          |
| `credentials/` | 凭证管理——API key 等          |
| `settings/`    | 用户设置——配置持久化          |
| `attachment/`  | 附件管理——内容寻址存储        |

#### 4. 交互与展示层

| 模块           | 说明                                      |
| :------------- | :---------------------------------------- |
| `host/`        | Web 服务端——HTTP 路由 + API 网关          |
| `client/`      | Web 浏览器端——React UI 组件               |
| `interaction/` | 人机协作——审批、确认对话框、ask-user 工具 |
| `feedback/`    | 人类反馈——评分、标注                      |
| `acp/`         | Agent Client Protocol——自动化/无头接入    |
| `sdk/`         | JSON-RPC SDK——外部程序对接                |

#### 5. 组合与分发层

| 模块          | 说明                                                       |
| :------------ | :--------------------------------------------------------- |
| `bundle/`     | Profile 补丁层——`base`、`web-app`、`headless` 三种预设组合 |
| `preset/`     | Agent 预设——per-session 的插件组合方案                     |
| `boot/`       | 启动引导——CLI 解析、Profile 加载、插件树组装               |
| `extensions/` | 运行时自修改——Agent 自己装卸插件                           |

#### 6. CLI 入口（`apps/cli`）

命令行入口，解析参数后通过 Profile 组合出完整的插件树并启动。

------

### 三、最终能做什么？

简单说，`dsh` 让你能运行一个功能完整的 AI Agent，它可以：

- 与大模型对话，自动调用工具完成任务
- 读写文件、执行命令、分析代码
- 在 Web UI（`http://127.0.0.1:3080`）中交互
- 以 headless 模式一次性执行任务
- 通过 SDK/ACP 被其他程序调用
- 支持子 Agent 协作、工作流编排
- 会话持久化、fork、回放

------

### 四、怎么使用？

最快启动方式：

npx @deepseek-ai/dsh web

从源码运行：

git clone https://github.com/deepseek-ai/deepseek-harness.git

cd deepseek-harness

pnpm install

pnpm run build

pnpm dsh web

Headless 模式（无 UI，直接执行任务）：

dsh --profile headless "帮我分析这个项目的架构"

查看实际加载的插件树：

dsh --profile web --dump-config

### 五、关于"万物皆插件"——自定义插件 + 打包集成

你听到的没错，这正是 dsh 的核心设计。回答你的问题：

#### 能否写自定义插件？

完全可以。 插件就是一个导出 Cordis `Service` 子类或函数的 npm 包。官方文档有专门的 cookbook：

- `docs/cookbook/adding-a-tool.md` — 添加新工具
- `docs/cookbook/adding-an-llm-adapter.md` — 添加新模型适配器
- `docs/cookbook/adding-a-package.md` — 添加新包的完整清单

一个最简插件的结构：

import { Service, Context } from '@deepseek-ai/cordis'

export default class MyPlugin extends Service {

  static inject = ['tools']  *// 声明依赖*

  constructor(ctx: Context, config: MyPlugin.Config) {

​    super(ctx, 'myPlugin')

​    *// 注册工具、监听事件等*

​    ctx.tools.register('my_tool', { ... })

  }

}

然后在 `cordis.patch.yml` 中挂载：

\- insert:

​    \- id: my-plugin

​      name: 'my-custom-plugin-package'

​      config:

​        key: value

#### 能否打包到自己的应用中？

可以，设计上就支持这种用法。 具体有几种集成方式：

1. Profile 方式 — 创建你自己的 Profile，列出需要的 bundle + 你的插件，`dsh --profile my-app` 即可启动
2. Bundle 方式 — 把你的插件组合打成一个 bundle（一个带 `cordis.patch.yml` 的 npm 包），可分发安装
3. SDK 集成 — 通过 Python SDK (`deepseek-harness-sdk`) 或 TypeScript SDK，以 JSON-RPC 调用 dsh 作为后端服务
4. ACP 协议 — 通过 Agent Client Protocol 远程控制
5. Headless 嵌入 — 用 headless profile 把 dsh 当作一个无 UI 的 Agent 引擎嵌入你的流程

典型场景举例：

假如你想做一个只需要"文件操作 + 代码分析 + 自定义工具"的精简 Agent 应用：

1. 写你自己的插件包（比如一个对接你内部系统的工具）
2. 创建一个自定义的 `cordis.patch.yml`，只保留你需要的核心插件 + 你的插件
3. 打包成一个 bundle，发布为 npm 包
4. 最终用 `npx @deepseek-ai/dsh --profile your-profile` 或通过 SDK 在你的应用中启动

整个架构是松耦合的——你不需要所有 226 个包，只需要 core spine + 你选择的能力插件 + 你自己的插件。不需要的功能完全可以不加载。

### 总结

| 维度     | 说明                                                     |
| :------- | :------------------------------------------------------- |
| 本质     | 一个插件化的 AI Agent 运行时框架                         |
| 核心框架 | Cordis（时空可组合性编程范式）                           |
| 配置方式 | YAML 声明式（`cordis.yml` / `cordis.patch.yml`）         |
| 可扩展性 | 任何部分都可被插件替换——包括 Agent 循环本身              |
| 集成方式 | CLI / Web UI / SDK / ACP / Headless                      |
| 状态     | Developer Preview（`0.1.0-rc.5`），会有 breaking changes |
