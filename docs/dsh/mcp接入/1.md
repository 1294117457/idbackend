## 一、前端 UI 插件

位置： `packages/client/ui-mcp-settings/`（和 `ui-settings-general` 同级）

要做的事：

| 文件                               | 作用                                                         |
| :--------------------------------- | :----------------------------------------------------------- |
| `src/client/index.ts`              | `apply(ctx)` 注册到 `settings.section` slot（和"通用""模型"并列的新 tab） |
| `src/client/McpSection.tsx`        | 设置页里的 "MCP 服务" 列表 UI                                |
| `src/client/McpForm.tsx`           | 添加/编辑 MCP Server 的表单（serverName、transport、command/url 等） |
| `src/client/McpSection.module.css` | 样式                                                         |
| `src/client/locales.ts`            | 中英文文案                                                   |
| `src/client/mcp-store.ts`          | 当前 MCP 列表状态                                            |

注册方式：

*// src/client/index.ts*

export const inject = ['slots', 'locale', 'connection']

export function apply(ctx) {

  ctx.slots.inject('settings.section', () => ctx.slots.register({

​    name: 'settings.section',

​    id: 'mcp',

​    order: 20,  *// 排在 general(0)、models(10) 后面*

​    label: () => t('mcp.nav'),

​    children: { 'settings.mcp.item': { kind: 'list', scope: 'root' } },

  }, McpSection))

}

## 二、后端接口

前端表单填完后，需要后端配合做两件事：

| 需要的后端能力    | 做什么                                                       | 怎么实现                                                     |
| :---------------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| 读写配置文件      | 把用户填的 MCP 配置写入 `~/.dsh/profiles/web/cordis.patch.yml` | 用 `ctx.settings` 或直接文件读写                             |
| 触发热重载        | 配置写入后让 dsh 重新加载插件树                              | HMR 自动处理（用户 patch 改了自动生效）                      |
| 查询当前 MCP 状态 | 前端显示哪些 MCP 已连接、状态如何                            | 通过 API 查询插件列表（就是你之前看到的 `api/pluginInventory/list`） |

可能需要新增的后端 API：

*// packages/host/ 下某个插件*

*// POST /api/mcp/servers — 添加一个 MCP 配置*

*// DELETE /api/mcp/servers/:id — 删除*

*// GET /api/mcp/servers — 列出当前配置的 MCP*

export function apply(ctx) {

  ctx.inject(['webServer'], (httpCtx) => {

​    httpCtx.webServer.route('GET', '/api/mcp/servers', async () => {

​      *// 读取当前 patch 文件中的 mcp-client 条目*

​      return listMcpEntries()

​    })

​    httpCtx.webServer.route('POST', '/api/mcp/servers', async (req) => {

​      *// 把新配置写入用户 cordis.patch.yml*

​      await writeMcpEntry(req.body)

​      *// HMR 自动触发重载*

​      return { ok: true }

​    })

  })

}

## 三、需要遵守的 MCP 规范

`@deepseek-ai/dsh-mcp-client` 已经实现了 MCP 协议， 你的 UI 不需要重新实现。你只需要生成正确的配置格式，传给已有的 `dsh-mcp-client` 插件。

配置 schema（你的表单需要收集的字段）：

interface McpServerConfig {

  serverName: string          *// 必填，唯一标识（如 "memory"、"github"）*

  transport: 'stdio' | 'streamable-http'  *// 必填，传输方式*

  *// stdio 方式需要：*

  command?: string            *// 可执行命令（如 "memorix"）*

  args?: string[]             *// 命令参数*

  env?: Record<string, string> *// 环境变量*

  cwd?: string                *// 工作目录*

  *// HTTP 方式需要：*

  url?: string                *// HTTP URL*

  headers?: Record<string, string> *// 请求头*

}

最终生成的 YAML 格式就是：

\- insert:

​    \- id: mcp-${serverName}

​      name: '@deepseek-ai/dsh-mcp-client'

​      config:

​        serverName: xxx

​        transport: stdio | streamable-http

​        command: xxx / url: xxx

​        ...

## 工作量评估

| 部分       | 复杂度 | 说明                                                     |
| :--------- | :----- | :------------------------------------------------------- |
| 前端 UI    | 中等   | 表单 + 列表 + 状态管理，参考 `ui-settings-models` 的做法 |
| 后端 API   | 较低   | 本质是读写 YAML 文件 + 查询插件状态                      |
| MCP 协议   | 不需要 | `dsh-mcp-client` 已经全实现了                            |
| 配置热重载 | 不需要 | HMR 已经内置，写文件就自动生效                           |

你主要的工作量在前端 UI。 后端只需要一个"读写配置文件"的薄接口，MCP 协议本身已经被 `dsh-mcp-client` 完整处理了。

## 为什么？

| 只做前端 UI 能行吗？                 | 分析                                |
| :----------------------------------- | :---------------------------------- |
| 前端能读写 `~/.dsh` 里的文件吗？     | 不能。 浏览器没有文件系统权限       |
| 前端能直接操作 cordis.patch.yml 吗？ | 不能。 配置文件在 Host（Node.js）上 |
| 前端能查询 MCP 连接状态吗？          | 需要通过 Host API 查询              |

所以前端必须通过后端 API 才能读写配置。

## 最少需要什么

my-dsh-plugins/

└── ui-mcp/

​    ├── src/

​    │   ├── index.ts          ← Host 侧：提供 API 接口（读写配置文件）

​    │   └── client/

​    │       ├── index.ts      ← Client 侧：注册 UI 到 settings

​    │       ├── McpSection.tsx

​    │       └── McpSection.module.css

​    └── package.json

一个包里可以同时有 Host 和 Client 代码。 很多 dsh 官方插件就是这么做的（你之前看到的 `ui-theme` 就有 `src/index.ts` 管 Host + `src/client/index.ts` 管 Client）。

------

## 不需要分成两个独立插件

| 方案                               | 说明                           |
| :--------------------------------- | :----------------------------- |
| 一个包，内含 host + client（推荐） | 和 `ui-theme` 一样的结构，简洁 |
| 两个独立包                         | 也行，但没必要增加复杂度       |

## 结构

my-dsh-plugins/ui-mcp/

├── package.json

│   {

│     "name": "dsh-plugin-ui-mcp",

│     "dsh": { "client": "./src/client/index.ts" }  ← 告诉 dsh 浏览器入口在哪

│   }

├── src/

│   ├── index.ts              ← Host 入口（Node.js 跑）

│   │   apply(ctx) {

│   │     ctx.webServer.route('GET', '/api/mcp/list', ...)

│   │     ctx.webServer.route('POST', '/api/mcp/save', ...)

│   │   }

│   │

│   └── client/

│       ├── index.ts          ← Client 入口（浏览器跑）

│       │   apply(ctx) {

│       │     ctx.slots.inject('settings.section', ..., McpSection)

│       │   }

│       ├── McpSection.tsx    ← UI 组件

│       └── McpSection.module.css

cordis.patch.yml 里还是只加一行：

\- insert:

​    \- id: ui-mcp

​      name: 'dsh-plugin-ui-mcp'

dsh 会自动识别这个包有 Host 部分和 Client 部分，分别加载到对应的 ctx 上。

------

## 一句话

一个插件包可以同时包含前后端代码，不需要拆两个。 Host 侧提供 API，Client 侧提供 UI，都在一个包里，配置只需一行。
