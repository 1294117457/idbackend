## 分数说明

- **score**：`[0, 1]` 归一化分数，top-1 固定为 1.0000，其余按 RRF 实际分比例缩放
- **rrf_score**：原始 RRF 融合分（用于调试），两路 rank-1 同时命中时理论最大 ≈ 0.0645
- **sources**：`["vector"]`=仅向量命中，`["bm25"]`=仅 BM25 命中，`["vector", "bm25"]`=两路同时命中（强信号）
- **source_id 折扣**：同文档第 2、3、4… 个 chunk 依次乘 0.77、0.63、0.53

**分数参考基准：**

| 情况 | rrf_score 范围 | score（归一化）|
|------|:---------------:|:-------------:|
| 双路 rank-1 同时命中 | ~0.064 | ~1.000 |
| 双路 rank-1+rank-2 | ~0.062 | ~0.95+ |
| 单路 rank-1 命中 | ~0.032 | ~0.50 |
| 单路 rank-5 命中 | ~0.029 | ~0.45 |
| 真正无关 | <0.010 | <0.15 |

## 调试信息

如果排序异常，按以下顺序排查：

1. **看 sources 字段**：两路都命中的 chunk 理应排名更高
2. **看 rrf_score 原始值**：归一化前的 RRF 分是否合理
3. **看 vector_rank 和 bm25_rank**：两路各自把该 chunk 排第几
4. **看 source_id 折扣**：同文档第 N 个 chunk 的 N 是多少
5. **重启服务**：确认新代码（rrf_k=30）已加载

## FAQ

**Q: score 是 1.0 但排在第 2？**

不可能。top-1 固定为 1.0。出现此情况请检查归一化代码。

**Q: score 0.95 是好还是不好？**

很好。说明该 chunk 是两路共识的结果，只是略逊于 top-1。

**Q: 为什么无关查询也有 score 0.3？**

因为归一化基准是 top-1 的 rrf_score。如果 top-1 本身就是弱命中（如两路都 rank-5），那 score 0.3 对应的实际区分度可能为零。此时看 rrf_score 更准确。

**Q: 2号文档还是占 top-5 中的 3 席？**

检查：1) 服务是否已重启；2) candidate_k 是否生效（看调试信息）；3) 同文档 chunk 出现在结果中的 vector_rank 和 bm25_rank 差异是否足够大
